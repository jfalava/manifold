`manifold` is the Manga Sync command line. It lives in `apps/migration` and
bundles everything the system needs a terminal for: the one-shot AniList ↔
MangaDex migrations, op-log triage, drift reconciliation against the canonical
registry, and registry backfill. The package is `@manifold/manifold-cli`; the
directory name is historical.

```text
bun run manifold <subcommand> [flags]
```

## Command tree

```text
manifold
├── migrate            One-shot AniList ↔ MangaDex migrations
│   ├── md2al          MangaDex library + read markers → private AniList entries
│   ├── al2md          Reverse: AniList list → MangaDex shelf + markers
│   └── wipe-al        NUKE all manga list entries + activities on AniList
├── ops                Personal API op-log triage
│   ├── pending        List pending / failed / blocked ops with details
│   └── retry          Reset one op back to pending
├── reconcile          Registry projection vs upstream state
│   └── diff           Live AniList list vs registry list state (read-only)
└── registry           Canonical registry maintenance
    ├── import         Snapshot the live AniList list into the registry
    ├── mangadex       Backfill MangaDex provider links
    └── comix          Backfill Comix hid links via local Chrome
```

## Configuration

Every remote-touching command resolves credentials the same way: explicit flag
→ bare env name → `ALCHEMY_SECRET_`-prefixed env name (the `iac/.env`
convention).

| Flag | Environment fallback | Used by |
|---|---|---|
| `--api-token` | `MANIFOLD_TOKEN` / `ALCHEMY_SECRET_MANIFOLD_TOKEN` | ops, reconcile, registry |
| `--api-origin` | `MANIFOLD_API_ORIGIN` | ops, reconcile, registry (default `https://manifold.jfa.dev/api`) |
| `--anilist-token` | `ANILIST_TOKEN` / `ALCHEMY_SECRET_ANILIST_TOKEN` | reconcile, registry |

AniList writes (migrations) always run from your machine — AniList blocks
Cloudflare Worker egress IPs, which is also why `anilist:*` ops in the log are
drained by the device rather than the Worker.

## Workflows

### Op-log triage

When the admin panel's op log shows something stuck:

```text
bun run manifold ops pending
bun run manifold ops retry --op-id <op_id>
```

`pending` prints every non-completed op with its id, kind, origin, attempt
count, and last error. Ops auto-retry up to 5 attempts before landing in
`blocked`; `retry` returns a blocked op to the queue. Remember *where* ops
execute: `mangadex:*` drains on the Worker, `anilist:*` waits for your device.

### Drift resolution

If you reorganized your AniList list directly on anilist.co, the registry
projection silently disagrees. Check, then resolve:

```text
bun run manifold reconcile diff     # read-only report
bun run manifold registry import    # align the registry to AniList
```

`reconcile diff` compares every live AniList manga entry against the
registry's recorded status and prints `DRIFT` / `NOT IN REGISTRY` lines with a
summary. `registry import` is the resolver: it lazy-mints registry rows for
every AniList entry and records the live status with `appliedRemotely: true`,
so **no ops are enqueued** — AniList already holds that state. It is
idempotent and safe to re-run after big AniList-side reorganizations.

### Comix hid backfill

`manifold registry comix` fills missing Comix provider links. comix.to's
JSON API is HMAC-signed and Cloudflare-gated, so the CLI does **not** replay
cookies through `fetch`. It captures `/browse?keyword=` inside a local Chrome
`Bun.WebView` (same JSON.parse hook as the Paperback source) and stores the
harvested jar in `Bun.secrets` (macOS Keychain / libsecret / Credential
Manager) until `cf_clearance` expires.

Dry-run by default; `--apply` writes. `--refresh-session` drops the stored
jar. `--chrome-cdp-url ws://127.0.0.1:9222/...` attaches to a Chrome already
exposing DevTools.

Turnstile still needs a real window. The command launches one itself, using
a dedicated `~/.manifold/comix-chrome` profile, because Chrome 136+ ignores
`--remote-debugging-port` on the default profile. Solve the check in that
window, then press Enter if the CLI asks.

```text
bun run manifold registry comix --apply
```

### Migrations

The original reason this CLI exists. `md2al` mirrors a MangaDex library into
private AniList entries (matching via external links, title search, and
Vectorize embeddings); `al2md` reverses the direction; `wipe-al` deletes all
manga list entries and manga-related activities on AniList.

Both migrations are **dry-run by default** — add `--apply` to write. `wipe-al`
prompts interactively unless `--yes` is passed. Phases are resumable; cached
snapshots and match results live under the CLI's `.tmp` directory (delete it
to force a fresh pass).

## Exit codes and output

Commands print human-readable tables and summaries. A non-zero exit code means
the command failed — most commonly an upstream HTTP error (AniList rate
limits: expect ~2.5 s spacing and 429 backoff on library-wide passes) or a
missing token.
