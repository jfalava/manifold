# Registry backup and recovery

The registry has two backup destinations. The application writes a private R2
snapshot daily at 03:00 UTC. `bun run backup` writes another R2 snapshot and an
independent archive on the machine running the command. Deploy and destroy run
that same backup command automatically before calling Alchemy.

Every independent archive includes all ten persistent tables, the original
OAuth encryption secret and other locally configured `MANIFOLD_*` credentials,
and a bundled recovery Worker. It is checksummed, restored into a fresh local
workerd namespace, compared table by table, written with mode 0600, and read
back for verification. OAuth session state is intentionally excluded.

Set `MANIFOLD_BACKUP_DIR` in `iac/.env` to a backup disk or independently backed-up
directory. The default is `.backups/` inside the checkout. Never put this
directory in Alchemy state, dependency caches, a public bucket, or source control.
The archive contains secrets in plaintext inside gzip, so treat it like `iac/.env`.
Copying it to public storage is unsafe. Disk encryption and encrypted backup
storage should protect copies at rest.

R2 recovery can lose up to a day of changes when the daily job succeeds.
Independent recovery reaches the last successful `bun run backup` or deployment.
For daily independent copies, run `bun run backup` from a scheduler on the backup
machine as well. Check command failures and archive timestamps. A laptop that is
asleep does not run a scheduled backup. No backup file is automatically expired.

## First deployment when the backup API does not exist

The deploy gate deliberately refuses a 404, authentication failure, or missing
backup. There is no skip-backup flag. Bootstrap from the current database without
deploying code first:

1. Run `bun run backup:bootstrap-sql`. It prints one read-only SQL statement.
2. In Cloudflare Data Studio, open the existing `manifold-api` / `ManifoldSync`
   object's database, the `default` object used by the API. Run that statement.
   Copy the `registry_backup` column's JSON value into a private, gitignored file
   such as `.backups/bootstrap.json`. Copy the JSON value itself, without a
   surrounding result array or CSV quoting. The single statement captures all
   tables consistently. Its bookmark is a label, not a PITR bookmark.
3. Run `bun run backup:pack .backups/bootstrap.json`. This verifies the encryption
   secret against every saved token and runs a complete restore drill. It prints
   an independent archive path.
4. Inspect `bun run plan`. Within 15 minutes of the SQL export, run
   `CI=1 bun run deploy -- --archive /absolute/path/to/ARCHIVE.recovery.json.gz --yes`.
   The supplied archive must pass the same restore drill and freshness check.
5. Run `bun run backup` after deployment to verify R2 upload, download, and the
   automatic backup path. Future deployments need no `--archive` argument.

Retention policies take effect when deployed. The Alchemy guard must be present
in the installed provider; `bun install` applies the pinned patch. Plan and deploy
check both published provider variants and refuse an unpatched installation.
Raw `alchemy deploy` and `alchemy destroy` also require a fresh archive when
loading this stack. An intentional edit to remove these safeguards, or direct
Cloudflare deletion with privileged credentials, can still bypass them.

## Restore an R2 snapshot into the existing service

List snapshots with `GET /api/v1/backups`, then POST
`{"key":"registry/TIMESTAMP-UUID.json","confirm":true}` to
`/api/v1/backups/restore` using the normal bearer token.

The server downloads and validates the snapshot before touching SQLite. It
checks the checksum and encryption-key fingerprint, saves the current state in
another R2 snapshot, then replaces all tables in one transaction. A failed insert
rolls the entire transaction back. The replaced state remains available in R2
if the wrong snapshot was selected. The JSON recovery limit is 16 MiB; oversized
snapshots fail explicitly rather than exhausting Worker memory.

Pause clients during recovery. Restoring historical outbox rows can replay older
provider writes, so background provider sync remains paused. Inspect registry
entries and queued operations before resuming it:

```sh
curl -X POST -H "Authorization: Bearer $MANIFOLD_TOKEN" \
  -H 'Content-Type: application/json' -d '{"confirm":true}' \
  https://manifold.jfa.dev/api/v1/backups/resume
```

## Recover when the API, namespace, or Cloudflare account is gone

Use an independent archive and credentials for the destination Cloudflare
account. The archive's old Cloudflare analytics token is not a credential for
the new account. The following creates a NEW namespace; it cannot overwrite a
nonempty registry.

```sh
bun install --frozen-lockfile
bun run backup:verify /absolute/path/to/ARCHIVE.recovery.json.gz
bun run recovery:prepare /absolute/path/to/ARCHIVE.recovery.json.gz \
  .recovery/incident manifold-recovery-incident
```

The new directory contains `worker.js`, `wrangler.jsonc`, `secrets.json`, and
`registry.json`. It is independent of Alchemy state, the router, Secrets Store,
and R2. Deploy that prepared bundle using Wrangler authenticated to the intended
account, then upload its secrets:

```sh
cd .recovery/incident
bunx wrangler@4.127.1 deploy --config wrangler.jsonc
bunx wrangler@4.127.1 secret bulk secrets.json --config wrangler.jsonc
```

Back in the repository root, pass the actual workers.dev URL returned by Wrangler:

```sh
bun run recovery:restore /absolute/path/to/ARCHIVE.recovery.json.gz \
  https://manifold-recovery-incident.YOUR-SUBDOMAIN.workers.dev
```

The standalone service exposes the normal authenticated `/v1` API. Read the
registry through it and verify entries, progress, and lists before pointing
clients at it. Background provider sync starts paused. Repeating the offline
import into this now-nonempty namespace is rejected.

The bundled Worker and plain JSON also support recovery without this checkout:
deploy the prepared directory and POST `registry.json` to `/recovery/restore`
with `Authorization: Bearer <archived MANIFOLD_TOKEN>` and
`X-Confirm-Restore: true`. Keep the token out of command-line arguments and logs.

Rebuild derived Vectorize indexes and bind AI/R2 before using search or scheduled
backups on the recovered service. Provider credentials may need reauthorization
if expired or revoked. Transfer the recovered namespace explicitly if moving it
to a different Worker; recreating a binding under the same class name does not
move its data. Preserve the archive until recovery and a new backup are verified.

Cloudflare also supports [SQLite point-in-time recovery for the previous 30
days](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/#pitr-point-in-time-recovery-api).
That is useful while the original namespace survives. Independent archives are
the recovery path when the account or namespace does not.
