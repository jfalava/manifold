```sh
manifold registry kagane [flags]
```

Backfills missing `kagane` provider links by searching Kagane's public catalog.
The command discovers exact title/alias candidates, verifies their external IDs
and series details, and never replaces an existing provider link. It is a dry
run unless `--apply` is supplied. Every run saves an incremental JSONL report.

Kagane has no personal API key. Search and details use public endpoints. Kagane
may challenge automated requests with Cloudflare; use the Chrome option below
when direct requests are challenged.

## Flags

### `--apply`

Write verified links to the registry. Writes use conflict rejection, so a
Kagane ID already owned by another row is never stolen.

```sh
manifold registry kagane --apply
```

### `--limit <n>`

Process at most `n` active rows missing a Kagane link. The complete registry is
loaded before this limit is applied.

```sh
manifold registry kagane --limit 25
```

### `--status <statuses>`

Filter rows by reading status. Use `auto` for all statuses, or a comma-separated
list such as `reading,completed`. `reading` includes `re_reading`.

```sh
manifold registry kagane --status reading,completed
```

### `--language <code>`

Filter Kagane records by translated language. Default: `en`.

```sh
manifold registry kagane --language en
```

### `--delay <milliseconds>`

Wait between Kagane requests, including retries. Default: `1500`. Requests run
sequentially; this is conservative pacing, not a published Kagane rate limit.

Transient network failures, HTTP 429, and HTTP 500/502/503/504 receive up to three
retries with exponential backoff. `Retry-After` seconds and HTTP dates are
honored. A cooldown over 120 seconds stops the run rather than retrying early.
Cloudflare challenges and malformed responses are not retried. Registry writes
are not retried by this catalog retry policy.

```sh
manifold registry kagane --delay 2000
```

### `--source-priority <names>`

Comma-separated Kagane source names, preferred first. Default: `MangaDex`.
Names are case-insensitive. Use `none` to disable source preference.

Each preferred source is searched before the full catalog. Only an external-ID
match can finish a source-scoped search early. A title-only match requires the
full catalog search. Source preference never overrides contradictory IDs or
chooses between multiple verified candidates within the same source.

```sh
manifold registry kagane --source-priority "MangaDex,VIZ Media"
```

### `--max-pages <n>`

Maximum pages per title search, including source-scoped searches. Default:
`200`, with 35 results per page. Every search must reach its final page before
its candidates can be selected. Repeated pages and incomplete searches are
errors, not catalog misses.

```sh
manifold registry kagane --max-pages 400
```

### `--report <path>`

Write a new JSONL report at this path. Default:
`~/.manifold/reports/kagane-<run>.jsonl`. Existing files are never overwritten.
Reports are created with owner-only permissions and do not contain tokens.

Records include run options, retries, each entry's outcome, inspected candidate
sources and external IDs, rejection reasons, and the final counts. Each entry
is written before the next entry starts, so completed results survive an
interrupted run. Reports are diagnostic records, not executable apply plans.

```sh
manifold registry kagane --report ./kagane-dry-run.jsonl
```

### `--chrome-cdp-url <url>`

Use an existing Chrome DevTools WebSocket for Kagane requests after solving a
Cloudflare challenge in that browser. Falls back to
`MANIFOLD_KAGANE_CHROME_CDP_URL`.

```sh
manifold registry kagane --chrome-cdp-url "ws://127.0.0.1:9222/devtools/browser/..."
```

The CLI uses a dedicated `~/.manifold/kagane-chrome` profile.

### `--anilist-token <token>`

Optional AniList token used to add English, romaji, native, and synonym aliases
to Kagane searches. Resolve order: flag → `MANIFOLD_ANILIST_TOKEN` →
`login anilist` keychain.

### `--api-token <token>` and `--api-origin <url>`

Credentials and origin for the Manifold registry API. The token falls back to
`MANIFOLD_TOKEN`; the origin defaults to `MANIFOLD_API_ORIGIN`, then
`https://manifold.jfa.dev/api`.

## Matching behavior

Kagane is an aggregator and can expose multiple source editions for one title.
The command compares AniList, MyAnimeList, and MangaDex work URLs from Kagane's
`series_links` against existing registry provider IDs. Any contradictory ID
rejects that candidate, even if another ID or the title matches. URL hosts and
work paths must match the actual provider, not just the link's label.

Externally verified candidates outrank title-only candidates. When multiple
verified candidates identify the same work, source priority selects a unique
candidate from the first available preferred source. Conflicting external IDs
between verified candidates remain unresolved. The command never chooses by
chapter count or search-result order.

Without matching external IDs, only a single exact-title candidate from the
full search can be linked. Language and source must agree, edition labels must
be absent, formats must be consistent, and books must be available. Ambiguous
and unverified records are reported but not written.

Completed runs with per-entry errors or ownership conflicts return a nonzero
exit code and print `Completed with errors` once. Successful links remain
saved. Reruns skip entries that already have a Kagane link.

## Usage

```sh
manifold registry kagane
manifold registry kagane --status reading --limit 50
manifold registry kagane --apply
```
