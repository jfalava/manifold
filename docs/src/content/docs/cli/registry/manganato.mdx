```sh
manifold registry manganato --chrome-cdp-url <browser-websocket-url> [flags]
```

Backfills missing `manganato` links on active registry entries. The external ID
is the native MangaNato manga slug. Runs are dry-run by default. `--apply` saves
verified links using conflict rejection and never replaces an existing binding.
Saved bindings can be attached by [PAS5 generation](/cli/pas5/).

## Terminal status

On a TTY, the command updates OSC 7501 program status and the window title together.
Rex can show the current step while the tab is unfocused, for example
`manifold: Checking MangaNato links 37%`. With `--apply`, the step becomes
`Checking and linking MangaNato`. Loading the registry, connecting to Chrome and
finalizing the report have no percentage. Row progress counts completed attempts
after status filtering and `--limit`, not successful matches.

Completion leaves `done`; errors, conflicts and unresolved challenges leave `error`.
Ambiguous and unmatched rows are completed findings, not failures.
Ctrl-C reports `idle` with the title `manifold: Cancelled`. This resets terminal
status but does not guarantee pending browser requests or report cleanup finish.
Interactive runs show `Waiting for MangaNato in Chrome` while paused for recovery.

Set `MANIFOLD_PROGRAM_STATUS=0` to disable both status reports and window-title
updates. Both are also disabled when stdout is redirected or `TERM=dumb`.
Terminal-status failures do not affect matching or registry writes.

## Use regular Chrome

Start a separate Chrome profile with loopback-only debugging on the desktop
runner. Open MangaNato and complete any challenge there.

```sh
open -na 'Google Chrome' --args \
  --user-data-dir="$HOME/.manifold/manganato-chrome" \
  --remote-debugging-address=127.0.0.1 \
  --remote-debugging-port=9224 \
  --no-first-run --no-default-browser-check https://www.manganato.gg/

curl -fsS http://127.0.0.1:9224/json/version
```

Pass the returned `webSocketDebuggerUrl` to `--chrome-cdp-url`, or set
`MANIFOLD_MANGANATO_CHROME_CDP_URL`. The URL changes when Chrome restarts.
Catalog requests execute inside Chrome with its cookies. Cookies are not copied
into CLI requests or reports. Chrome for Testing remained challenged in the
initial test; regular Chrome loaded the catalog, but that does not guarantee
future challenge clearance.

```sh
manifold registry manganato --status reading,planning,on_hold --limit 10 \
  --chrome-cdp-url 'ws://127.0.0.1:9224/devtools/browser/<id>'
```

## Matching and limits

The matcher reads aliases and author/artist credits from an existing MangaDex
binding. MangaDex supplies identity evidence, not MangaNato's chapter content.
Missing or unavailable credits cannot produce automatic title-only links, except
for specifically user-confirmed work/listing pairs.

Reviewed MangaNato slugs are bound to exact AniList IDs for Kichiku Eiyuu / Savage
Hero, Nigasanai yo? Fukuroji-kun, Yumemi ga Oka Wonderland, Marika's Love Meter
Malfunction, Ii Fuufu no Hanashi / A Happy Couple, and Yuki Nee-chan no Kannou
Gokko, plus Ore no Ichizu wo Jama Suru Aitsu, Dark Summoner to Dekiteiru,
Himegoto Kakushigoto, Mada Kimi wo Miageteru, My Girlfriend Is a Colossal Cutie,
Hotel Inhumans, The New Gate, Kuma to Usagi wa Tomodachi dewa Irarenai,
Mikoto-chan wa Kirawaretakunai!, Haha no Ai wa Mama Naranai!, Assassin & Cinderella,
Moto Azadarake no Kanojo ga Shinpai de, The Erotical Wizard and His Twelve Brides,
Garbage Brave / Garbage Hero, Koisuru Futari wa Kiba wo Kakusu, Tatakai Shika
Shiranai Onna Kishi wo Amayakashi Tsuzuketa, Otaku ni Tsumetai Gal, Mainichi Ie ni
Kuru Gal ga Kyorikan Zero demo Yasashikunai, Cool na Doukyuusei no 10-nengo,
and Demon X Angel Can't Get Along!. These confirmations supply identity evidence
even when credits are missing or differ. They do not establish global author aliases.
The command reads those listings directly instead of repeating broad searches;
known competitors from the resume report remain included. Titles are still
revalidated, and confirmations do not extend to unreviewed slugs or other works.
Dorei wo Choukyoushite Harem Tsukuru remains manual because its publication-title
change leaves an unresolved choice of updating version.

Two explicit listing choices override duplicate ranking for their bound AniList IDs:
`153502` uses `quinpath-romance`, because the user reported broken images on
`konsei-wa-goen-ga-arimasu-you-ni`; `130872` uses `fuzoroi-no-renri`, as selected
by the user over the side-stories and alternate listings. Only the chosen listing
requires a detail read; other remembered IDs remain in report history without
blocking that choice. Its title and identity must still validate. Failure never
falls back to another listing, and ownership conflicts still prevent writes.
These choices do not confirm side stories as the same edition. The command does
not test chapter images, and a recent update date does not prove they work.

Discovery uses up to three distinct English or romanized MangaDex title variants.
Other translations remain available for identity checks but do not add searches.
The registry title is a discovery fallback when tagged aliases are unavailable.
Common title words such as `the`, `world`, `heroine` and `reincarnated` are excluded
from individual-word queries. Broader words such as `welcome`, `home`
and `boss` remain fallbacks but rank behind more distinctive words such as
`okaeri` or `kenzokuka`, even across title variants. Queries use single words
because MangaNato treats multiple words as alternatives, not a narrower search.
Identical queries run only once per entry.
Empty, unrelated or capped searches try the next planned word or title variant.

If those plans do not complete with a candidate, discovery tries up to six untried
words from the registry and canonical English/romanized titles. This rescue pass
is independent of the three-variant cutoff and includes words beyond each title's
first two. It alternates between titles so one long name cannot consume all six
queries. Reports record these queries in `discovery.rescueQueries`.

If word searches find no exact-title candidate, discovery tries up to three
deduplicated complete titles. The registry title comes first, followed by canonical
English/romanized MangaDex names, independently of the three-variant word-search
cutoff. Full-title searches retain common words, so titles such as `Young Again`
can still be searched. MangaNato can rank the exact title first while also returning
unrelated word matches; every page must still complete within the search budget.
The fallback does not run when word searches already found a candidate, even in a
capped query, or when remembered competitors have an ambiguous result. Matched dry
runs and interrupted full-title searches can be revalidated on resume, retaining
all competitors. Full-title hits do not bypass identity or chapter
checks. Reports identify these planned fallbacks in `discovery.fullTitleQueries`.
Search policy 7 lets `--resume` retry older unmatched/deferred rows while preserving
completed ambiguity reviews. Titles with no usable word or full-title query remain
deferred.

If no useful query completes, the default policy continues **one** capped query
that yielded a validated exact-title candidate, up to 20 total pages. It prefers
single-word queries in plan order, then full titles. Cached pages retain their
original age and count toward the ceiling. Only clean pagination exhaustion marks
the query complete; a next link on page 20 still means deferred. All competitors
and other capped-query evidence remain available to identity checks. The report
updates the same attempt with its final `maxPages` and `continued: true`.
This does not guarantee a short run: the six rescue queries can add up to 30 pages,
and continuation can fetch another 15 when its first five pages are cached.

Search results must match a complete known title or alias after punctuation,
spacing, case and accent normalization.
Numbers and edition suffixes remain significant. Author/artist matching allows
reversed name order and parenthetical credits.
Confirmed full-author aliases also match, including `Sano Yuto` /
`Yuuto Sano`, `Ohtsuki Ichika` / `Ootsuki Ichika` and `Necoco` / `Nekoko`.
These equivalences do not apply to other authors with similar spellings.
Unconfirmed fuzzy author matches are not accepted. Without an explicit listing
confirmation, missing credits on either side still require manual review, even
when chapter counts agree.

Evidence scores use 60 points for an exact title/alias, 40 for a verified
author/artist or user-confirmed listing, and 25 for chapter support from either
basis below. A match needs at least 85 points, an exact title and either nonmissing
credits on both sides or an explicit listing confirmation. These are policy
weights, not confidence probabilities. Chapter agreement can support different
credited names; disagreement never penalizes a verified-author match.

For duplicates with different nonmissing names, the command first compares complete
chapter inventories against an exact-title listing with directly verified author/artist
credits. At least 10 shared positive integer chapter positions and 95% overlap
with the smaller integer inventory supply chapter support. Fractional-only positions
do not stand in for integers. A chapter-supported candidate cannot anchor another
candidate, and missing credits cannot be rescued. This is an exact-title plus
verified-author-anchor heuristic, not verification of chapter content or author aliases.

Missing-credit duplicates can receive a separate opt-in recommendation.
Each must match an exact known title/alias and independently meet the same
10-integer-chapter and 95% overlap thresholds against a directly author-verified
anchor. Inferred candidates cannot anchor one another. Recognizable edition
markers in primary titles, such as side stories, one-shot, novel or remake, must
agree with the registry title; a shared alias does not bypass this check.
Recommendations require a useful completed query, no capped or incomplete queries,
and complete comparable inventories. They use the same chapter-superset ranking
and update-date tie-break below, including the active-listing fallback. Missing or
conflicting evidence leaves no recommendation. The report records `recommendation`
with the candidate ID, basis, inferred overlap evidence, `requiresOptIn: true` and
`acceptEligible`. Acceptance requires continuous positive integer positions from
chapter 1 through the last integer. Sparse recommendations, including numbered
outliers, remain review-only.

**`--apply` alone never accepts inference.** Add `--accept-recommendations` to
preview accepted recommendations in a dry run, then combine both flags to save
them. The command prints and records the inference evidence and any lost positions
before a provider write. Reports record `acceptedRecommendation` separately;
original `eligible` and `userConfirmed` evidence never changes. Resume carries
decisions as history, not permanent identity confirmation.

Probable joined/split author spellings such as `Kanalina` / `Lina Kana` appear as
unconfirmed suggestions in the report. They never update the confirmed alias map.
Chapter support adds 25 points once, even when multiple sources support it.

For still-unresolved different names, the command reads the already-bound AniList work, or resolves
an already-bound MAL ID through AniList. No token is required and no title search
is used to obtain a convenient total. Returned IDs must agree with existing
bindings. Only a `FINISHED` work with a positive integer total of at least 10
chapters contributes support, and the candidate must also match a title/alias on
that canonical record. Ongoing works, unknown totals and short works add no points.
This uses AniList's total, not a direct MAL API total.

Strong support requires a complete numbered MangaNato inventory starting at
chapter 1. Fractional positions collapse to integer chapter buckets for this
signal. Their count must be within 5% of the canonical total, at least 95% of
positions through the last bucket must exist, and no bucket may exceed 105% of
the total. Split uploads, sparse inventories and extreme numbered outliers cannot
manufacture agreement. The normal distinct-position count still ranks duplicates.

Discovery stops after the first fully paginated query that itself returns a
detail-validated exact-title candidate. It consumes all pages of that query,
including later-page competitors, but does not require the remaining aliases to
finish. This trades search recall for fewer requests: unsearched aliases can hide
other listings. It does not prove catalog-wide completeness. A capped query's
candidates cannot link just because a later unrelated or empty query completes.
Previously known competitors are retained and revalidated even when the useful
query does not return them. Duplicate inventories come from `/api/manga/<slug>/chapters`.
Every competitor must qualify through author evidence or chapter-supported
identity, or a scoped user confirmation. Prefer the listing with the most distinct
chapter positions only when it contains every competitor's positions. If each
listing has chapters the other lacks, strict selection cannot choose one.
A smaller listing does not win merely because it is closer to the canonical total.
Duplicate
uploads of the same position count once; the highest chapter number is not a
count. Reports record limited discovery coverage, attempted queries as complete,
capped, partial or failed, omitted queries/titles, and the useful completed query.
They also retain candidate origins, canonical provenance, verified-anchor overlap
counts and thresholds, evidence scores, author classification, unconfirmed alias
suggestions, coverage and the selected listing across resume chains.

When strict chapter-superset ranking fails, an active-listing fallback can select
a newer listing despite lost zero or fractional positions. Every competitor must
still pass identity checks and have a complete comparable inventory with a valid
chapter-update date. Primary-title edition markers must agree with the registry
title. The winner must contain a continuous integer run `1..N`, include every
competitor's positive integer positions, advance beyond **each** competitor's
integer set, and have a strictly newer chapter-update date than every competitor.
Equal integer sets, missing dates, gaps and sparse numbered outliers cannot use
this fallback. Explicit user-selected listings and manual publication conflicts
keep their existing behavior.

Reports record `selection.basis: "active-listing"` and `selection.lostPositions`
by competing slug. The same losses appear before saving a link. Fractional positions
may be split story chapters, not just bonus content; selection does not merge or
verify content. The strict ranking remains the first choice.

MangaNato coverage counting tolerates identical same-page chapter records: a repeated
slug with the same normalized numeric position counts once. Negative chapter numbers
are excluded from scoring and reported, including the observed case where Chapter 1
and Chapter -1 share `chapter-1`. This does not remove source content or verify that
the negative chapter is readable. Pagination still uses every raw record.
Other conflicting numbers for one slug, repeated unknown numbers, and slugs repeated
across pages remain errors. An unknown number still makes coverage incomparable.

Floating-point noise such as `58.300000000000004` normalizes to `58.3` for scoring
only. The shortest decimal within two relative machine-epsilon units, capped at
an absolute difference of `0.000000000001`, is used when it needs at most 12 decimal
places. Other values remain unchanged. Real multipart positions such as `58.1`,
`58.2` and `58.31` remain distinct. Source slugs and displayed chapter labels do not
change. Reports include `coverage.inventory` with raw record, duplicate record,
excluded negative record and normalized record counts. Normalization counts raw
nonnegative records before deduplication, so these diagnostics are not disjoint;
`coverage.count` is the distinct normalized position count.

When leading listings have identical nonempty chapter-position sets, prefer the
one with the latest valid chapter `updated_at`. This is a provider chapter-update
time, not necessarily original publication or upload time. Every chapter in each
tied listing must have a valid timestamp; missing, invalid, future or tied dates
leave selection ambiguous. Reports retain `coverage.latestChapterUpdatedAt` as
epoch milliseconds. Cache fetch time never breaks a tie. Old version-1 chapter
inventory caches are refetched once because they discarded these timestamps;
search and detail caches remain reusable.

All-empty or unnumbered duplicate inventories and insufficient identity evidence
remain ambiguous. An unconfirmed unknown-author competitor is not discarded in favor
of a verified listing. Missing credits do not stop query pagination or prevent
duplicate inventory reads, so review reports retain chapter evidence even when
automatic selection is impossible. Failed or inconsistent inventory reads remain
retryable errors; a challenge pauses an interactive run. Existing bindings are never replaced.
Incomplete discovery is never recorded as a completed query.
Unavailable canonical lookups leave unresolved candidates retryable on resume.
These are catalog counts, not verification of chapter images. Ads labelled as
numbered chapters can contribute one position, and split/combined releases can
affect counts. A larger count does not guarantee a superset of the other listing.
MangaNato's extension is an English source; the matcher
does not detect the language of individual chapters.

- `--delay <ms>` defaults to `4000` between catalog requests.
- Without `--max-pages`, searches start at `5` pages and one candidate-bearing
  capped query can continue to `20`. An explicit `--max-pages <n>` is a hard ceiling
  and disables that automatic continuation, including explicit `--max-pages 5`.
  If no query completes with an exact-title candidate, capped searches become
  `deferred`, not `unmatched` or linked. Inventory requests retain the original
  ceiling, default `5`, each requesting up to 9000 chapters. Malformed pagination
  and repeated pages remain errors.
- `--limit <n>` limits eligible rows after loading the complete registry.
- `--status <statuses>` uses the shared registry status filter, default `auto`.
- `--report <path>` creates a new JSONL report instead of overwriting a file.
  The default is `~/.manifold/reports/manganato-<run>.jsonl`.
- `--api-origin` and `--api-token` override the usual Manifold API configuration.

Reports persist progress, candidates, title/author evidence and each row's
outcome as the run proceeds. In an interactive terminal, Cloudflare challenges,
HTTP 403/429 and catalog request timeouts pause the sweep on the current request.
Inspect MangaNato in regular Chrome, resolve any challenge or connection problem,
then press Enter in the CLI to retry. No catalog requests run while waiting.
Repeated restrictions pause again. A timeout alone is not treated as proof of a
Cloudflare challenge. The same recovery applies to a challenge during startup.

Successful recovery continues the same row without repeating completed searches,
details or inventory pages. The report records the pause as progress, not a
completed row outcome. Without interactive stdin, or if stdin closes while
waiting, the sweep stops and leaves that row retryable. Ctrl-C stops the run.
Earlier successful applied links remain saved. Inspect the report before applying
a larger run.

## Resume after an interruption

If the run stopped rather than recovered in place, rerun with the same options and add
`--resume <report.jsonl>`. Use the current browser WebSocket URL if Chrome restarted.

```sh
manifold registry manganato --status reading,paused,planning --delay 4000 --apply \
  --resume "$HOME/.manifold/reports/manganato-<previous-run>.jsonl" \
  --chrome-cdp-url 'ws://127.0.0.1:9224/devtools/browser/<current-id>'
```

Completed unchanged checks, including ambiguous and unmatched results, are skipped
before `--limit`. Errors, conflicts, challenged rows and rows interrupted before
their result was saved are retried. Failed author lookups remain retryable.
Dry-run matches are rechecked when adding `--apply`; reports never replay writes.
Successful existing bindings are skipped; removed bindings can be checked again.

`deferred` entries are skipped on resume while their registry inputs, page budgets
and search-policy version are unchanged. Change `--max-pages`, correct the entry's
identity links/title, or omit `--resume` to try them again. Entries with no usable
Latin/numeric word or full-title queries are also deferred. Older untyped page-limit errors
retry once under the new policy; they are not assumed to be catalog misses.
Discovery-policy changes can recheck earlier unmatched results. A separate
selection-policy version reopens old ambiguities once when author matching or
chapter ranking changes.
Selection policy 11 rechecks earlier ambiguities for the active-listing fallback;
search policy 7 retries earlier discovery misses with canonical-word rescue and
one bounded candidate-bearing continuation. Adding
`--accept-recommendations` also reopens unchanged
ambiguities previously checked without that flag. Accepted dry-run matches are
revalidated when adding `--apply`. Saved provider bindings remain untouched.
Known competing IDs survive resume chains and are revalidated even if the current
queries no longer return them. After evaluation under the same selection policy,
unchanged ambiguities are skipped again.

Validated search pages, inventory pages and successful candidate details are saved immediately
as `catalog` events. Resumes reuse those reads for up to 24 hours from each original
fetch time. If page 3 is challenged, a resume can reuse pages 1 and 2 and fetch
page 3 again. Cached pages still count toward `--max-pages`; partial searches never
become complete results. Finishing a query does not renew its earlier pages' age.
Older reports' complete-query caches remain readable, but they cannot recover
uncached pages from an interrupted query. Inventory caches are separate from old
detail records, which do not contain chapter data. Missing inventories are fetched,
never interpreted as zero chapters.
Matching and current ownership checks still run before any write. Cached reads
can miss catalog changes during that window; omit `--resume` to fetch fresh data.

Every resumed run creates a new report, carries earlier checkpoints forward, and
leaves its input untouched. Resume from the newest report after another stop.
`--report` can choose the new output path but cannot name an existing file.
Reports from new runs validate the API origin and changed title/provider inputs.
Older MangaNato reports are supported using entry ID and title only: use them
only for the same registry with unchanged identity links. They cannot detect old
metadata failures or changes to provider IDs; omit `--resume` for a fresh check.
