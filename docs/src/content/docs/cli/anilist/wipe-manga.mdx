```sh
manifold anilist wipe manga [flags]
```

**Destructive.** Port of the AniList manga bulk-delete approach: scans your
AniList profile, then deletes **all** manga list entries and **all**
manga list activities. Text posts are preserved unless you explicitly opt in
with `--include-text-activities`; post text cannot be reliably classified as
manga-related. Anime list entries and anime list activities are never touched.

The command scans and reports what it would delete by default. `--apply` enables deletion and still prompts for confirmation. Pass `--yes` with `--apply` only when you intend to skip that prompt.

## Flags

### `--apply`

Permanently delete the scanned AniList manga list entries and manga-related
activities. Without this flag, the command only scans and reports the data.

- Default: `false`

Example:

```sh
manifold anilist wipe manga --apply
```

### `--yes`

Skip the interactive confirmation prompt. This flag has an effect only when
combined with `--apply`.

- Default: `false`

Example:

```sh
manifold anilist wipe manga --apply --yes
```

### `--include-text-activities`

Also target your text posts, without guessing whether they are manga-related.
Default: `false`. Preview the count in a dry run before deciding to delete them.
Deletion still requires `--apply` and confirmation (or `--yes`).

```sh
manifold anilist wipe manga --include-text-activities
```

### `--anilist-token <token>`

Optional AniList access token override. Resolve order: flag → `MANIFOLD_ANILIST_TOKEN` → `login anilist` keychain.

Example:

```sh
manifold login anilist
manifold anilist wipe manga
```

## Usage

```sh
manifold anilist wipe manga
manifold anilist wipe manga --apply
bun run manifold anilist wipe manga --apply --yes
```

If both the manga list and targeted activities are empty, the command exits
without deleting anything. An empty list alone does not prevent activity deletion.

<Aside type="danger" title="Irreversible">
  This permanently removes manga list state and activity history on AniList.
  Prefer exporting or migrating first if you still need the data.
</Aside>
