## Verified restore procedure: start with an empty database

Verified on September 9, 2026: a full Reading, Paused, and Planning test
archive restored into a fresh Paperback installation retained saved library
membership. Every title checked had working MangaDex, Comix, and MANIFOLD
attachments.

1. Keep a separate full backup of your library and reading history before
   deleting anything. The successful test archive contained no reading history.
2. Start with a genuinely empty Paperback database. Delete App, rather than
   Offload App, was used for the fresh-install test. Do not restore an older
   backup or open/add titles before importing the test archive.
3. Install MangaDex, Comix, and MANIFOLD, then restore the prepared `.pas5`.
4. Run Paperback's database repair **before opening any imported title**.
5. Open titles from each category and provider, leave, and reopen them to
   verify that they remain saved. Export the Realm database and PAS5 before
   attempting manual fixes if any title fails.

The tested archive used uppercase **internal library and source-object UUIDs**.
Actual provider manga IDs were unchanged. It contained 561 entries: 341 Reading,
95 Paused, and 125 Planning. Of these, 547 had all three providers, 12 lacked one
reader-provider link, and two were tracker-only. Missing registry links cannot
be replaced with invented provider IDs.

This was a specially prepared test archive, not unmodified CLI output. The
current generator still creates lowercase random library/source UUIDs and skips
titles without a reader-provider link. Do not assume its output is identical to
the tested archive. Uppercase UUIDs and repair were tested together; neither is
established as sufficient on its own.

Restoring a backup replaces the visible library but does not necessarily remove
old source objects or cached chapters. Realm exports showed titles split between
an unattached object holding chapters and another object holding library
membership. Repair did not merge those duplicates. A previously opened title
continued to fail while newly tested titles worked after repair. These findings
explain why an existing installation is not equivalent to the fresh-database
test; they do not establish Paperback's exact internal failure mechanism.

```text
bun run manifold anilist create pas5 [flags]
```

Builds a source-free Paperback `.pas5` archive. Every imported title has a
canonical registry UUID, at least one registry-linked native **MangaDex** or
**Comix** attachment, and **MANIFOLD**. Native providers own reading and
chapter updates; the tracker owns canonical progress synchronization.

Titles without a registry UUID or a linked native content provider are skipped.

## After restoring: run Paperback database repair

Run Paperback's **database repair** after restoring a generated archive, then
check that a title keeps its library category when you leave and reopen it.
Keep the original backup until this check passes.

In device testing on September 9, 2026, imported titles appeared in the library
but reopened as Uncategorized despite exported Reading memberships. Database
repair restored category persistence without changing library IDs, timestamps,
tabs, or attachments. Provider IDs were valid; changing UUID casing alone did
not fix the problem. This is a verified workaround for the tested case, not a
confirmed explanation of Paperback's internal failure.

## `filter`: isolate providers in an existing archive

Filter an existing backup offline, without AniList credentials, registry lookups,
or new IDs. Exclude one or two providers with `--exclude-mangadex`,
`--exclude-comix`, and `--exclude-tracker` (MANIFOLD). `--input` and `--out`
are required and must point to different files. Without `--apply`, this is a dry run.

```text
bun run manifold anilist create pas5 filter --input generated.pas5 --out mangadex-only.pas5 --exclude-comix --exclude-tracker --apply
bun run manifold anilist create pas5 filter --input generated.pas5 --out comix-only.pas5 --exclude-mangadex --exclude-tracker --apply
bun run manifold anilist create pas5 filter --input generated.pas5 --out tracker-only.pas5 --exclude-mangadex --exclude-comix --apply
```

This diagnostic subcommand deliberately retains tracker-only libraries. It
preserves existing library IDs, tabs, timestamps, and retained source metadata.
Entries without a remaining attachment are omitted and counted; missing provider
links are never invented. Excluded sources, their chapters and progress markers,
and unreferenced manga metadata are removed. Other providers are left unchanged.

Keep the original backup and test the outputs separately: restoring may replace
the device library. A tracker-only archive tests saved/tracking behavior, not
chapter reading. Normal generation below still requires a native content provider.

## Flags

### `--apply`

Write the generated `.pas5` archive. Without this flag, the command reports
the titles and output it would generate without writing the archive.

- Default: `false`

Example:

```text
bun run manifold anilist create pas5 --apply
```

### `--tabs <value>`

Choose which AniList statuses become Paperback library tabs. Use `auto` to
include the default status set, `none` to create no status tabs, or pass a
comma-separated list of `reading`, `paused`, `dropped`, `completed`, and
`planning`.

- Default: `auto`

Example:

```text
bun run manifold anilist create pas5 --tabs reading,completed
```

### `--base <path>`

Seed the generated archive from an existing `.pas5` export. Existing tab IDs
are reused when possible, which helps preserve device tab references. Titles
already present in the backup are enriched with missing MangaDex and Comix
attachments. Existing attachments with a different provider ID and ambiguous
matches are reported and left unchanged. All ManifoldSource attachments are
removed, orphan source/info rows are pruned, and libraries left with only a
tracker are dropped.

- Default: no base archive

Example:

```text
bun run manifold anilist create pas5 --base ./Paperback-Backup.pas5
```

### `--out <path>`

Set the path for the generated archive.

- Default: `Paperback-Generated.<date>.<time>.pas5`

Example:

```text
bun run manifold anilist create pas5 --out ./backups/manifold.pas5
```

### `--limit <n>`

Generate entries for only the first `n` titles. This is useful for a canary
archive before exporting the complete AniList list.

- Default: no limit

Example:

```text
bun run manifold anilist create pas5 --limit 10
```

### `--anilist-token <token>`

Optional AniList access token override. Resolve order: flag → `MANIFOLD_ANILIST_TOKEN` → `login anilist` keychain.

Example:

```text
bun run manifold login anilist
bun run manifold anilist create pas5
```

### `--api-token <token>`

Personal API token used to resolve registry UUIDs and provider links. Falls
back to `MANIFOLD_TOKEN`.

Example:

```text
bun run manifold anilist create pas5 --api-token "$MANIFOLD_TOKEN"
```

### `--api-origin <url>`

Personal API origin used for registry lookups.

- Default: `https://manifold.jfa.dev/api` (or `MANIFOLD_API_ORIGIN`)

Example:

```text
bun run manifold anilist create pas5 --api-origin https://manifold.example/api
```

## Usage

```text
bun run manifold anilist create pas5
bun run manifold anilist create pas5 --apply
bun run manifold anilist create pas5 --apply --base ./Paperback-Backup.pas5 --tabs reading,completed
```

`--tabs` filters which AniList statuses become library tabs. Install the
MangaDex and Comix extensions before restoring an archive that contains their
attachments. With `--base`, existing tab IDs are reused when possible;
restoring the generated archive on a device may **replace** the on-device
library — keep a copy of the original backup.
